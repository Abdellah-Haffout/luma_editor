# 00 - نظرة عامة على المعمارية والرؤية (Architecture Overview)

## 1. المشكلة في المحررات التقليدية

تعتمد المحررات الشائعة (مثل Unity، Unreal، Godot، وBlender) على النموذج التالي:
* شجرة المشهد الكلاسيكية (Scene Hierarchy Tree).
* لوحة الخصائص المزدحمة (Inspector / Property Panel).
* منفذ رؤية عام وحيد (Global Viewport).

**نقاط الضعف في هذا النموذج:**
1. **التشتت والحمل الإدراكي الزائد (UI Clutter & Cognitive Overload):** عند تحديد أي كائن في المشهد، يمتلئ المفتش (Inspector) بعشرات المكونات (Transform, Mesh, PBR Material, Physics, Audio, Scripts...)، ويصبح التعديل على جزء دقيق مصحوباً بضجيج بصري كبير.
2. **غياب وضوح تدفق البيانات (Opaque Dataflow):** يصعب فهم كيف تؤثر الأصول (Assets) على الكائنات، ومن أين تأتي المواد، وكيف تتكامل العناصر إجرائياً.

## 2. الرؤية المعمارية لـ Luma Editor

يقدم **Luma Editor** مفهوماً جذرياً: **محرر مبني بالكامل على الـ Node Graph من البداية إلى النهاية**.

المساحة الرئيسية للمحرر ليست منفذ رؤية تقليدي يحيط به قوائم، بل هي **مساحة رسم عقدية (Node Graph Canvas)**، حيث كل عنصر في المشهد يولد أو يُعالج عبر عقدة (Node).

```
   ┌─────────────────────────────────────────────────────────────────┐
   │                       Luma Editor Canvas                        │
   │                                                                 │
   │  ┌──────────────┐       ┌──────────────┐       ┌─────────────┐  │
   │  │ AssetLoader  │──────▶│  Mesh Node   │──────▶│ Entity Node │  │
   │  │ (3D Model)   │       │ [Mini-View]  │       │  [Preview]  │  │
   │  └──────────────┘       └──────┬───────┘       └─────────────┘  │
   │                                │                      ▲         │
   │                         [Dive-In Button]              │         │
   │                                │                      │         │
   │                         ┌──────▼───────┐              │         │
   │                         │Material Node │──────────────┘         │
   │                         │  (PBR Graph) │                         │
   │                         └──────────────┘                         │
   └─────────────────────────────────────────────────────────────────┘
```

### الثنائية المعمارية: Macro vs Micro View

1. **المستوى الكلي (Macro View - The Graph Canvas):**
   * يعرض البنية الهندسية وتدفق البيانات للمشهد بالكامل.
   * تحتوي كل عقدة على بطاقة بصرية تفاعلية تعرض معاينة مصغرة (Mini-Viewport) لحالتها الراهنة.
   * الأسلاك تمثل تدفق البيانات والمكونات والتحويلات.

2. **المستوى البؤري (Micro View - The Dive-In / Focus Mode):**
   * تمتلك كل عقدة إمكانية التوسع (Expand / Dive-In).
   * عند الدخول في العقدة: تتوسع مساحتها لتملأ نافذة العمل بالكامل وتتحول إلى **محرر متخصص مستقل**.
   * **مبدأ العزل وتحديد المسؤولية (Single Responsibility Principle):**
     * عند الدخول إلى `Mesh Node`: تظهر **فقط** أدوات تعديل الهندسة (Gizmos، محاذاة النقاط، أبعاد المجسم). لن تظهر أدوات الشيدر أو الصوت أو التصادمات!
     * عند الدخول إلى `Material Node`: تظهر **فقط** أدوات الألوان، القوام (Textures)، والـ PBR.

## 3. الطبقات المعمارية الأساسية (Layered Architecture)

تم تقسيم البنية التحتية إلى 3 طبقات رئيسية لضمان العزل الكامل وسهولة الاختبار:

```
┌────────────────────────────────────────────────────────────────────────┐
│  الطبقة 3: طبقة التفاعل وعرض الواجهة (Presentation & Interaction)       │
│  - تحويل الإحداثيات (Pan / Zoom).                                      │
│  - إدارة التحديد (Selection Box).                                      │
│  - مسار التنقل (Breadcrumb & Focus Stack).                             │
│  - رسم الواجهة عبر bevy_luma (SDF Canvas, Cards, Wires).               │
├────────────────────────────────────────────────────────────────────────┤
│  الطبقة 2: محرك التراجع والمعاملات (Transaction & History Engine)      │
│  - نمط الأوامر العكسية (Reversible Command Pattern).                   │
│  - المعاملات المركبة (Compound Transactions).                          │
│  - دمج العمليات المستمرة (Action Merging / Debounce).                  │
├────────────────────────────────────────────────────────────────────────┤
│  الطبقة 1: نموذج البيانات الصافي (Core Graph Model)                     │
│  - النودات (Nodes) والمنافذ (Pins) والأسلاك (Connections).             │
│  - قواعد التحقق الصارمة (Strict Validation) ونظام الأنواع.             │
│  - كشف الحلقات (DAG Cycle Detection).                                  │
│  * خالية بنسبة 100% من أي اعتماد على مكتبات الرسوميات أو Bevy UI.       │
└────────────────────────────────────────────────────────────────────────┘
```

## 4. دور محرك Bevy ومكتبة `bevy_luma`

* **`bevy_luma`:** تستخدم كطبقة العرض والواجهة الأساسية (SDF-based World Space UI)، مما يمنح مساحة الـ Graph استجابة فائقة، نعومة رسومية، وتكبير/تصغير فكتورياً بدون تشويش.
* **Bevy Render Targets:** تُستخدم لتوليد المعاينات المصغرة (Mini-Viewports) داخل بطاقات النودات عبر كاميرات فرعية ترسم إلى `Image / Texture` مخصصة، ويتم تحويلها بسلاسة إلى العرض الكامل عند الـ Dive-In.
