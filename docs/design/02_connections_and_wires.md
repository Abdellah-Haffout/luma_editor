# 02 - نظام الأسلاك والتوصيل (Connections & Wires)

يعالج هذا المستند منطق التحقق (Validation)، آلة حالة التوصيل التفاعلية (Interactive Wiring State Machine)، وحساب المسارات الهندسية للأسلاك.

---

## 1. قواعد التحقق من صحة التوصيل (Validation Rules)

لا يمكن إنشاء أي سلك في `Luma Editor` إلا إذا اجتاز بنجاح مصفوفة التحقق التالية:

```
[محاولة التوصيل: Pin A ───▶ Pin B]
          │
          ├── 1. هل الاتجاه صالح؟ (Output -> Input) ────▶ [خطأ: اتجاهات غير متوافقة]
          │
          ├── 2. هل النودان مختلفان؟ (A.node != B.node) ─▶ [خطأ: اتصال ذاتي غير مسموح]
          │
          ├── 3. هل الأنواع متطابقة؟ (Type Compatibility) ──▶ [خطأ: عدم توافق النوع]
          │
          ├── 4. هل السعة متوفرة؟ (Capacity Check) ──────▶ [إما استبدال أو خطأ]
          │
          └── 5. هل ينشئ السلك حلقة؟ (Cycle / DAG Check) ─▶ [خطأ: تكون حلقة مغلقة]
                    │
                    ▼
            [اتصال صالح ومقبول ✅]
```

### تفصيل شروط التحقق:

1. **شرط الاتجاه (Direction Invariance):**
   * يجب أن يكون المصدر دائماً `PinDirection::Output` والهدف دائماً `PinDirection::Input`. إذا قام المستخدم بسحب السلك بالعكس (من Input إلى Output)، يقوم النظام تلقائياً بقلب المصدر والهدف منطقياً لتبسيط التجربة.
2. **شرط الانفصال (Self-Connection Prevention):**
   * لا يمكن لمخرج نود أن يتصل بمدخل نفس النود.
3. **توافق الأنواع (Type Compatibility):**
   * يجب أن يتطابق `DataType` بين المنفذين، أو يكون هناك محول ضمني (Implicit Converter).
4. **سياسة سعة المدخل (Input Capacity Policy):**
   * إذا كان المدخل يقبل اتصالاً واحداً فقط (`PinCapacity::Single`) وكان هناك سلك سابق:
     * **السياسة الافتراضية:** قطع السلك القديم واستبداله بالسلك الجديد تلقائياً مع تسجيل ذلك في الـ `Undo` كعملية ذرية واحدة.
5. **كشف الحلقات الدائرية (Cycle Detection):**
   * يتم استخدام خوارزمية البحث بالعمق (DFS) للتأكد من أن إضافة السلك لن تجعل المسار يعود إلى النود الأصلي.

---

## 2. آلة حالة التوصيل التفاعلي (Interactive State Machine)

تتفاعل الأسلاك مع مؤشر الماوس عبر آلة حالة محددة:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum WiringState {
    /// الوضع الطبيعي: لا يوجد سحب نشط
    Idle,
    
    /// جاري سحب سلك جديد من منفذ ما
    DraggingNew {
        source_pin: PinId,
        current_cursor_canvas: Vec2,
    },
    
    /// جاري إعادة توجيه سلك موجود مسبقاً (Re-wiring)
    Reconnecting {
        connection_id: ConnectionId,
        fixed_pin: PinId,
        moving_pin_direction: PinDirection,
        current_cursor_canvas: Vec2,
    },
}
```

### سلوك المؤشر والتغذية البصرية (Visual Feedback):
* عند السحب، تضيء جميع المنافذ المتوافقة في الـ Canvas باللون **الأخضر**.
* المنافذ غير المتوافقة تظهر بلون باهت أو **أحمر** عند التمرير فوقها مع منع الإفلات.
* إذا أفلت المستخدم السلك في مساحة فارغة:
  * يختفي السلك بسلاسة، أو تفتح قائمة سياقية صغيرة تقترح إنشاء نود متوافق فوراً.

## 3. التمثيل الهندسي لمنحنى السلك (Cubic Bézier Spline)

ترسم الأسلاك باستخدام منحنيات بيزيير التكعيبية (Cubic Bézier Curves) لتعطي إحساساً سلساً بالمرونة:

$$B(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3 \quad (t \in [0, 1])$$

* **$P_0$ (نقطة البداية):** مركز منفذ الـ Output.
* **$P_3$ (نقطة النهاية):** مركز منفذ الـ Input (أو موقع الماوس أثناء السحب).
* **$P_1, P_2$ (نقاط التحكم):**
  * يتم حساب المماس أفقياً بناءً على المسافة بين المنفذين:
    $$\Delta x = |P_3.x - P_0.x| \times 0.5$$
    $$P_1 = P_0 + (\Delta x, 0)$$
    $$P_2 = P_3 - (\Delta x, 0)$$

هذا يضمن أن السلك يخرج دائماً بشكل مستقيم وسلس من المنفذ قبل أن ينحني نحو الهدف.
